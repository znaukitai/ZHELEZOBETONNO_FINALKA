# Mog Battle Bot

Телеграм-бот для рейтинга и батлов среди студентов колледжа (aiogram 3.4.1, Python 3.11, SQLite).

## Как это работает

- Регистрация: имя + номер студенческого (номер нужен только против дублей, нигде не показывается).
- Батл: игрок присылает 3 фото лица, бот считает score (1–10) по симметрии и пропорциям лица
  (MediaPipe Face Mesh + OpenCV) и ищет соперника по эло.
- Побеждает тот, у кого score выше. Старт 1000 эло, победа/поражение ±25, при разрыве больше 1.0 — ±28.
  Минимум 0, максимума нет.
- Подбор: сначала ±200 эло, каждые 30 секунд диапазон шире на 100, через 5 минут поиск отменяется.
- Топы: день и неделя (прирост эло за период, по времени UTC+5), всё время (общее эло). По 100 мест,
  в формате «Имя · Telegram ID».
- Фото не сохраняются: обрабатываются в памяти и сразу забываются.
- Отсев фото: слишком тёмные/пересвеченные, смазанные, без лица, больше одного лица, голова повёрнута.

**Важно:** score — собственная метрика, а не настоящий PSL. Пороги и формула в разделе `5. SCORING` файла `bot.py`,
их нужно подкрутить на реальных фото.

## Админ

Один человек (`ADMIN_ID`). Команда `/admin` или кнопка «🛠 Админка» в меню:
статистика, поиск игрока, удаление, ручная правка эло, рассылка (с подтверждением).

## Файлы

Весь код бота лежит в одном файле `bot.py`. Внутри он разбит на разделы (ищи по заголовкам `# 1. CONFIG` … `# 9. MAIN`):

| Раздел в `bot.py` | Что внутри |
|---|---|
| `1. CONFIG` | настройки, правила эло и подбора, картинки меню |
| `2. DATABASE` | SQLite (встроенный `sqlite3`), файл и таблицы создаются сами, функции `db_*` |
| `3. ELO` | сколько очков стоит батл |
| `4. MATCHMAKING` | очередь поиска соперника |
| `5. SCORING` | оценка фото и фильтры (MediaPipe + OpenCV) |
| `6. UI` | клавиатуры и экраны с картинкой |
| `7. HANDLERS` | регистрация, меню, профиль, топы, батл |
| `8. ADMIN` | админ-панель |
| `9. MAIN` | запуск |

Остальные файлы проекта:

| Файл | Зачем |
|---|---|
| `requirements.txt` | зависимости Python |
| `runtime.txt`, `.python-version` | версия Python (3.11) |
| `Procfile` | команда запуска `python bot.py` |
| `railpack.json` | системные библиотеки для OpenCV на Railway |
| `.gitignore` | не коммитить `.venv`, `.env`, кэш, файлы базы `*.db` |

## Переменные окружения

| Переменная | Что это |
|---|---|
| `BOT_TOKEN` | токен от @BotFather (в код не вставлять!) |
| `ADMIN_ID` | Telegram ID админа |
| `DB_PATH` | необязательно: путь к файлу базы SQLite. По умолчанию `mogbot.db` рядом с ботом, а на Railway с подключённым Volume файл лежит в нём сам |

Отдельная база данных не нужна: все данные хранятся в одном файле SQLite.

## Запуск локально

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
export BOT_TOKEN="..." ADMIN_ID="..."
python bot.py
```

Файл `mogbot.db` появится рядом с `bot.py`.

## Деплой на Railway

1. Залей проект в GitHub (токена в коде быть не должно).
2. Railway → New Project → Deploy from GitHub repo.
3. У сервиса бота, вкладка Variables, добавь `BOT_TOKEN` и `ADMIN_ID`.
4. **Подключи Volume**, иначе база будет стираться при каждом деплое: у сервиса бота Settings → Volumes → New Volume (или правый клик по сервису → Attach Volume), путь монтирования `/data`. Бот сам найдёт его и положит базу в `/data/mogbot.db`. Если хочешь другой путь, задай `DB_PATH`.
5. Деплой запускается сам. Системные библиотеки для OpenCV (`libgl1` и др.) и команда запуска
   `python bot.py` заданы в `railpack.json`, отдельных переменных для них не нужно.
6. Нужен ровно один запущенный экземпляр бота: два одновременно (например, локально и на Railway)
   будут конфликтовать за обновления.

Python 3.11 задан в `runtime.txt` и `.python-version`: у `mediapipe 0.10.14` нет сборок под 3.13,
а это версия по умолчанию.

**Важно:** без Volume файловая система Railway временная, и при каждом деплое или перезапуске
все игроки и рейтинг пропадут. Для бекапа периодически скачивай файл базы `mogbot.db` из Volume.

## Если что-то не собирается

- `libGL.so.1` / `libxcb` / `libgthread` при старте: убедись, что `railpack.json` лежит в корне
  репозитория и список `deploy.aptPackages` в нём не пустой. Если не помогло, самый надёжный путь —
  свой `Dockerfile` на `python:3.11-slim` с `apt-get install libgl1 libglib2.0-0` перед
  `pip install -r requirements.txt`.
- `No module named 'cv2'` после ручных `pip uninstall opencv-*`: не удаляй пакеты OpenCV вручную,
  `mediapipe` сам тянет нужный.
- Картинки меню не показываются: в `bot.py` → раздел `1. CONFIG` → `PHOTOS` нужны прямые ссылки на изображение
  (`https://i.ibb.co/.../file.jpg`) или Telegram `file_id`, а не ссылки на страницы ibb.co.
  Пока ссылка не работает, бот показывает экран текстом.

## Безопасность

- Токен старого бота из чата считай скомпрометированным: @BotFather → `/revoke`.
- Секреты только в переменных окружения, `.env` в `.gitignore`.
